# Technical Specification: HH.ru Auto-Responder & Job Tracker Bot

## 1. Назначение проекта

Локальное приложение на Node.js / TypeScript без графического интерфейса (работает в фоне на ПК). Всё управление происходит через Telegram-бота. Приложение ищет вакансии на HH.ru по фильтрам, генерирует уникальные сопроводительные письма через локальную нейросеть (Gemma 4:64k в Ollama), отправляет отклики с защитой от блокировок, отслеживает ответы работодателей и выгружает статистику в Excel.

---

## 2. Технологический стек (Bleeding-Edge Stack)

- **Платформа (Runtime):** **Node.js v26+** (использование нативного запуска TypeScript и встроенного модуля базы данных `node:sqlite`).
- **Язык и компилятор:** **TypeScript 7 (`tsgo` / `@typescript/native-preview`)** — сверхбыстрая проверка типов и компиляция на базе Go, без использования устаревших экспериментальных декораторов.
- **Архитектура:** Чистый модульный TypeScript (Clean Modular Architecture) на классах и нативных ES-модулях (`ESM`), без тяжелых фреймворков.
- **База данных:** Нативный **`node:sqlite`** + **Drizzle ORM (`drizzle-orm`, `drizzle-kit`)** — современная легковесная и строго типизированная ORM, хранящая данные в локальном файле `database.sqlite`.
- **Валидация данных:** **`zod`** — проверка типов для ответов от API, настроек и структурированных ответов от нейросети.
- **Telegram-бот:** **`grammy`** + **`@grammyjs/conversations`** — современный фреймворк для Telegram-ботов и пошаговых диалогов.
- **HTTP-клиент:** **`ofetch`** — современный клиент поверх нативного `fetch` с авто-повторами запросов и перехватчиками (interceptors) для обновления токенов OAuth 2.0.
- **Фоновые задачи:** **`croner`** — быстрый планировщик фоновых задач для автооткликов и проверки ответов работодателей.
- **Нейросеть (LLM):** Официальный клиент **`ollama`** (или прямые запросы через `ofetch`) к локальной модели `gemma4:64k`.
- **Таблицы и файлы:** **`exceljs`** (генерация `.xlsx` отчетов), **`unpdf`** (современная библиотека для чтения текста резюме из PDF).

---

## 3. Архитектура и структура папок

Проект строится на простых классах, которые передаются друг другу напрямую (ручное внедрение зависимостей в `main.ts`), что обеспечивает 100% совместимость с `tsgo`:

```text
src/
├── main.ts                  # Точка входа: консольный опрос при первом старте и запуск всех сервисов
├── db/
│   ├── index.ts             # Подключение к встроенному node:sqlite через Drizzle ORM
│   └── schema.ts            # Описание таблиц базы данных (AppSetting, UserProfile, SearchFilter, ApplicationRecord)
├── modules/
│   ├── config-store/        # ConfigStoreService — чтение и запись настроек в SQLite
│   ├── telegram/            # TelegramBotService — кнопки, команды, визард настройки
│   ├── hh-api/              # HhApiService — OAuth2, поиск, резюме, отклики через ofetch
│   ├── llm/                 # LlmService — генерация сопроводительных писем через Gemma 4:64k
│   ├── scheduler/           # SchedulerService — фоновые циклы на базе croner + контроль лимита (<= 100 в день)
│   └── exporter/            # ExcelExporterService — выгрузка в .xlsx и задел под Google Sheets

```

## 4. Схема базы данных (SQLite)

1. **`AppSetting`** (Таблица настроек: ключ — значение):

- `TG_BOT_TOKEN` — токен вашего Telegram-бота.
- `TG_ADMIN_ID` — ваш личный ID в Telegram (чтобы бот слушался только вас).
- `HH_CLIENT_ID` и `HH_CLIENT_SECRET` — ключи приложения HH.ru.
- `HH_ACCESS_TOKEN`, `HH_REFRESH_TOKEN`, `HH_TOKEN_EXPIRES_AT` — токены авторизации OAuth 2.0.
- `LLM_BASE_URL` — адрес локальной нейросети (по умолчанию `http://127.0.0.1:11434`).
- `LLM_MODEL_NAME` — название модели (по умолчанию `gemma4:64k`).
- `AUTO_APPLY_ENABLED` — включен ли автоотклик (`true` / `false`).
- `DAILY_LIMIT` — максимальное количество откликов в сутки (по умолчанию `50`, **строгое ограничение: от 1 до 100**).

2. **`UserProfile`** (Данные кандидата):

- `id` (Int, PK)
- `hhResumeId` (String) — ID выбранного резюме на HH.ru.
- `resumeRawText` (String) — полный текст резюме для передачи в нейросеть.
- `customPromptRules` (String, Optional) — ваши пожелания к стилю сопроводительных писем.

3. **`SearchFilter`** (Настройки поиска вакансий):

- `id` (Int, PK)
- `queryText` (String) — ключевые слова, название должности, стек.
- `excludedWords` (String, Optional) — слова-исключения.
- `areaId` (String, Optional) — код региона (например, `113` — Россия, `1` — Москва).
- `schedule` (String, Optional) — график работы (`remote`, `fullDay`).
- `salaryFrom` (Int, Optional) — желаемая зарплата от.

4. **`ApplicationRecord`** (История всех отправленных откликов):

- `id` (Int, PK)
- `vacancyId` (String, Unique) — ID вакансии (чтобы никогда не откликаться дважды на одну вакансию).
- `negotiationId` (String, Optional) — ID диалога с работодателем на HH.
- `companyName` (String) — название компании.
- `positionTitle` (String) — название вакансии.
- `salaryText` (String) — зарплата (текстом).
- `vacancyUrl` (String) — ссылка на вакансию.
- `coverLetter` (String) — текст отправленного сопроводительного письма.
- `status` (String) — текущий статус (`response` — отправлено, `invitation` — приглашение, `discard` — отказ).
- `lastEmployerMessage` (String, Optional) — сообщение от работодателя.
- `isNotified` (Boolean) — отправлено ли уведомление вам в Telegram.
- `appliedAt` (DateTime) — точная дата и время отправки отклика (используется для подсчета дневного лимита).
- `updatedAt` (DateTime) — время последнего обновления статуса.

## 5. Пошаговая логика работы приложения

### 5.1. Первый запуск в консоли (CLI Bootstrap)

1. При запуске программы на ПК она проверяет, есть ли в базе `TG_BOT_TOKEN` и `TG_ADMIN_ID`.
2. Если их нет (первый запуск), программа прямо в окне терминала просит ввести токен бота и ваш Telegram ID, сохраняет их в базу и запускает бота.
3. В дальнейшем менять эти данные или любые другие ключи можно прямо через меню настроек в самом Telegram-боте (или при необходимости перезаписать при старте).

### 5.2. Первичная настройка внутри Telegram и OAuth 2.0

1. Когда вы пишете боту `/start`, он проверяет ваш `TG_ADMIN_ID` (чужим пользователям бот не отвечает).
2. Бот запускает диалог настройки:

- Спрашивает `Client ID` и `Client Secret` от HH API.
- Формирует ссылку для входа через **OAuth 2.0** и присылает её в чат.
- Вы переходите по ссылке, нажимаете «Разрешить» на сайте HH и копируете полученный код (`code`) обратно в чат бота.
- Бот автоматически меняет этот код на рабочие токены (`access_token` и `refresh_token`), сохраняет их и в будущем обновляет их сам без вашего участия.
- Бот скачивает список ваших резюме с HH, предлагает выбрать нужное кнопкой, а также позволяет загрузить файл резюме (PDF/текст) для более точного анализа.
- Бот спрашивает теги, стек и параметры для поиска вакансий, а также желаемый **дневной лимит откликов (число от 1 до 100)**.

### 5.3. Генерация сопроводительного письма через Gemma 4:64k

1. Для каждой найденной вакансии программа берет текст вашего резюме и описание вакансии.
2. Отправляет запрос в локальную нейросеть `gemma4:64k`.
3. Нейросеть пишет уникальное сопроводительное письмо, опираясь только на реальные факты из вашего резюме и требования конкретной вакансии.

### 5.4. Фоновые автоотклики и контроль дневного лимита (до 100 в сутки)

1. В меню бота есть кнопки:

- `▶️ Запустить / ⏸ Остановить автоотклики`
- `🎯 Лимит откликов в день (текущий: X/100)` — позволяет в любой момент изменить лимит в боте. При вводе числа программа проверяет условие: `1 <= limit <= 100`. Если введено больше 100, бот сообщает об ограничении безопасности и ставит `100`.

2. Когда автоотклик включен, фоновый процесс работает по следующему циклу:

- **Проверка лимита:** Считает количество записей в таблице `ApplicationRecord`, у которых дата `appliedAt` относится к сегодняшнему дню (с `00:00:00` текущих суток).
- Если `количество_за_сегодня >= DAILY_LIMIT`, процесс останавливается до следующих суток, а бот присылает сообщение: _«Дневной лимит откликов (X шт.) достигнут. Автоотклики продолжатся завтра»_.
- Если лимит не исчерпан: ищет новые вакансии по вашим фильтрам, генерирует письмо через LLM, отправляет отклик в HH API и сохраняет запись в БД.
- Делает случайную паузу **от 2 до 5 минут** перед следующим откликом, чтобы HH.ru не требовал капчу и не блокировал аккаунт.

### 5.5. Уведомления об ответах и работа после выключения ПК

1. Каждые 15 минут (а также **сразу при запуске приложения на ПК**) запускается проверка статусов `syncNegotiations()`.
2. Программа запрашивает у HH API актуальные статусы всех ваших откликов.
3. Если работодатель прислал приглашение, отказ или сообщение — данные в базе обновляются, а флаг `isNotified` становится `false`.
4. Бот находит все записи с `isNotified == false`, присылает вам в Telegram уведомление с названием компании, должностью, статусом и текстом ответа от HR, после чего ставит `isNotified = true`. Благодаря этому вы не пропустите ни одного ответа, даже если компьютер был выключен несколько дней.

### 5.6. Отчеты в Excel и задел под Google Таблицы

1. По нажатию кнопки `📊 Скачать Excel-отчет` в боте программа формирует файл `.xlsx` и присылает его в чат.
2. В таблице содержатся колонки: **Компания**, **Позиция**, **Зарплата**, **Дата отклика**, **Статус**, **Сопроводительное письмо** и **Ссылка на вакансию**.
3. Код выгрузки строится через единый интерфейс `IReportExporter`: сейчас активен `ExcelExporterService`, и рядом создается подготовленный шаблон `GoogleSheetsExporterService` для легкого подключения Google Docs/Sheets в будущем.

## 6. Пошаговый план разработки для ИИ-агента (Фазы)

- **Фаза 1 (Основа, TypeScript 7 и база данных):** Инициализировать проект под Node.js 26 (`"type": "module"`), подключить компилятор TypeScript 7 (`@typescript/native-preview` / `tsgo`), настроить **Drizzle ORM** со встроенным драйвером `node:sqlite`, описать таблицы в `src/db/schema.ts`, написать сервис настроек `ConfigStoreService` и консольный опрос при первом запуске в `src/main.ts`.
- **Фаза 2 (HH API и нейросеть):** Написать `HhApiService` (авторизация OAuth 2.0, автообновление токенов, загрузка резюме, поиск вакансий, отправка отклика, проверка статусов) и `LlmService` (подключение к Ollama `gemma4:64k`).
- **Фаза 3 (Telegram-бот и меню):** Собрать бота на `grammy`, сделать пошаговый диалог настройки (OAuth2, выбор резюме, фильтры), добавить главное меню и настройку дневного лимита (с проверкой `<= 100`).
- **Фаза 4 (Фоновая автоматизация):** Реализовать воркер автооткликов с проверкой дневного лимита и случайными паузами, а также воркер проверки ответов работодателей при старте ПК и по расписанию.
- **Фаза 5 (Экспорт в Excel):** Написать генератор `.xlsx` отчетов через `exceljs`, привязать его к кнопке в боте и создать интерфейс-заглушку для Google Sheets.
