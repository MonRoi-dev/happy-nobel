# Technical Specification: HH.ru Auto-Responder & Job Tracker Bot

## 1. Назначение проекта

Локальное приложение на Node.js 26 / TypeScript 7 без графического интерфейса (работает в фоне на ПК). Всё управление происходит исключительно через Telegram-бота. Приложение ищет вакансии на HH.ru по заданным фильтрам, генерирует уникальные сопроводительные письма на основе резюме через локальную нейросеть (Gemma 4:64k в Ollama), автоматически отправляет отклики в фоне, отслеживает ответы работодателей (приглашения, отказы) и выгружает отчеты в Excel.

---

## 2. Технологический стек (Bleeding-Edge Stack)

- **Платформа (Runtime):** **Node.js v26+** (нативный запуск TypeScript и использование встроенного модуля базы данных `node:sqlite`).
- **Язык и компилятор:** **TypeScript 7 (`tsgo` / `@typescript/native-preview`)** — сверхбыстрая проверка типов и компиляция на базе Go, без использования устаревших декораторов.
- **Архитектура:** Чистый модульный TypeScript (Clean Modular Architecture) на классах и нативных ES-модулях (`"type": "module"`), без тяжелых фреймворков.
- **База данных:** Встроенный **`node:sqlite`** + **Drizzle ORM (`drizzle-orm`, `drizzle-kit`)** — хранение всех настроек и истории откликов в локальном файле `database.sqlite`.
- **Валидация данных:** **`zod`** — проверка типов для настроек, фильтров и ответов от API.
- **Telegram-бот:** **`grammy`** + **`@grammyjs/conversations`** — управление приложением, меню и пошаговые диалоги настройки.
- **Работа с HH.ru (Гибридный подход):**
    - **`ofetch`** — быстрые запросы к открытому публичному API (`https://api.hh.ru/vacancies`) для поиска и чтения описаний вакансий без ключей.
    - **`playwright`** (Chromium) — браузерная автоматизация с постоянной сессией (`launchPersistentContext` в папке `./hh-session`) для входа в аккаунт соискателя, парсинга резюме, отправки откликов и проверки статусов переговоров.
- **Фоновые задачи:** **`croner`** — планировщик задач для цикла автооткликов и периодической проверки ответов работодателей.
- **Нейросеть (LLM):** **`ollama`** (или запросы через `ofetch` к `http://127.0.0.1:11434/api/generate`) для генерации сопроводительных писем моделью `gemma4:64k`.
- **Таблицы и файлы:** **`exceljs`** (генерация `.xlsx` отчетов), **`unpdf`** (чтение текста резюме из PDF-файла при загрузке через бота).

## 3. Архитектура и структура папок

Проект строится на независимых классах-сервисах, которые инициализируются и связываются в `src/main.ts`:

```text
src/
├── main.ts                  # Точка входа: консольный опрос при первом старте и запуск всех сервисов
├── db/
│   ├── index.ts             # Подключение к встроенному node:sqlite через Drizzle ORM
│   └── schema.ts            # Описание таблиц базы данных (AppSetting, UserProfile, SearchFilter, ApplicationRecord)
├── modules/
│   ├── config-store/        # ConfigStoreService — чтение и запись настроек в SQLite
│   ├── telegram/            # TelegramBotService — кнопки, команды, визард настройки
│   ├── hh-hybrid/           # HhHybridService — поиск через ofetch + авторизация, отклики и статусы через Playwright
│   ├── llm/                 # LlmService — генерация сопроводительных писем через Gemma 4:64k
│   ├── scheduler/           # SchedulerService — фоновые циклы на базе croner + контроль лимита (<= 100 в день)
│   └── exporter/            # ExcelExporterService — выгрузка в .xlsx и задел под Google Sheets

```

## 4. Схема базы данных (SQLite / Drizzle ORM)

1. **`app_settings`** (Таблица настроек: ключ — значение):

- `key` (Text, Primary Key) — ключи конфигурации:
- `TG_BOT_TOKEN` — токен Telegram-бота.
- `TG_ADMIN_ID` — личный Telegram ID владельца (защита от чужих пользователей).
- `HH_IS_LOGGED_IN` — статус входа в браузерную сессию HH (`true` / `false`).
- `LLM_BASE_URL` — адрес локальной нейросети (по умолчанию `http://127.0.0.1:11434`).
- `LLM_MODEL_NAME` — название модели (по умолчанию `gemma4:64k`).
- `AUTO_APPLY_ENABLED` — включен ли автоотклик (`true` / `false`).
- `DAILY_LIMIT` — максимальное количество откликов в сутки (по умолчанию `50`, **строго от 1 до 100**).

- `value` (Text) — значение настройки.

2. **`user_profile`** (Данные кандидата):

- `id` (Integer, Primary Key)
- `hhResumeTitle` (Text) — название выбранного резюме на HH.ru.
- `resumeRawText` (Text) — полный текст резюме (из профиля HH или из загруженного в бота PDF/текста) для передачи в нейросеть.
- `customPromptRules` (Text, Nullable) — дополнительные пожелания пользователя к стилю писем.

3. **`search_filters`** (Настройки поиска вакансий):

- `id` (Integer, Primary Key)
- `queryText` (Text) — ключевые слова, название позиции, стек.
- `excludedWords` (Text, Nullable) — слова-исключения.
- `areaId` (Text, Nullable) — код региона (например, `113` — Россия, `1` — Москва).
- `schedule` (Text, Nullable) — график работы (`remote`, `fullDay`).
- `salaryFrom` (Integer, Nullable) — минимальная зарплата.

4. **`application_records`** (История отправленных откликов):

- `id` (Integer, Primary Key, Auto-increment)
- `vacancyId` (Text, Unique) — ID вакансии на HH (защита от повторных откликов).
- `companyName` (Text) — название компании.
- `positionTitle` (Text) — название позиции.
- `salaryText` (Text) — зарплата (отформатированная строка).
- `vacancyUrl` (Text) — ссылка на вакансию.
- `coverLetter` (Text) — сгенерированное сопроводительное письмо.
- `status` (Text) — текущий статус (`response` — отправлено, `invitation` — приглашение, `discard` — отказ, `viewed` — просмотрено).
- `lastEmployerMessage` (Text, Nullable) — текст ответа работодателя.
- `isNotified` (Integer / Boolean) — отправлено ли уведомление в Telegram.
- `appliedAt` (Text / ISO DateTime) — дата и время отправки отклика (для подсчета дневного лимита).
- `updatedAt` (Text / ISO DateTime) — время последнего обновления статуса.

## 5. Пошаговая бизнес-логика приложения

### 5.1. Первый запуск в консоли (CLI Bootstrap)

1. При старте (`src/main.ts`) программа проверяет наличие `TG_BOT_TOKEN` и `TG_ADMIN_ID` в таблице `app_settings`.
2. Если их нет, в терминале запускается интерактивный опрос (`node:readline/promises`): пользователь вводит токен бота и свой Telegram User ID. Данные сохраняются в SQLite, после чего бот запускается.
3. В дальнейшем изменить токен, ID или настройки LLM можно прямо через меню настроек внутри Telegram-бота.

### 5.2. Первичная настройка в Telegram, вход в HH и загрузка резюме

1. Бот отвечает только пользователю с `TG_ADMIN_ID`.
2. При команде `/start` или нажатии кнопки `🔑 Войти в HH.ru` бот запускает метод `loginInteractive()` в `HhHybridService`:

- На ПК открывается видимое окно браузера Chromium (`headless: false`) на странице `https://hh.ru/account/login` с привязкой к папке `./hh-session`.
- Пользователь входит в свой аккаунт (по СМС или паролю).
- Как только программа обнаруживает успешный вход, она сохраняет сессию, автоматически считывает текст резюме со страницы `/applicant/resumes`, закрывает видимое окно браузера и присылает в Telegram уведомление: _«Вход выполнен успешно!»_.

3. Дополнительно в боте есть кнопка `📄 Загрузить резюме (PDF / Текст)` — пользователь может прислать PDF-файл резюме в чат, бот извлечет из него текст через `unpdf` и сохранит в `user_profile.resumeRawText`.
4. Далее пользователь в боте задает ключевые слова поиска (`search_filters`) и дневной лимит откликов (`DAILY_LIMIT`, от 1 до 100).

### 5.3. Генерация сопроводительного письма через Gemma 4:64k

1. Для каждой найденной вакансии `LlmService` берет сохраненный текст резюме и полное описание вакансии (очищенное от HTML-тегов).
2. Отправляет запрос в локальную модель `gemma4:64k` через Ollama API.
3. Промпт требует написать краткое, живое и персонализированное сопроводительное письмо на русском языке (до 1200 символов) строго на основе реального опыта из резюме.

### 5.4. Фоновые автоотклики и контроль дневного лимита (до 100 в сутки)

1. В меню бота есть переключатель `▶️ Запустить / ⏸ Остановить автоотклики` и кнопка `🎯 Лимит откликов в день (X/100)`. При вводе числа больше 100 бот принудительно ограничивает значение до `100`.
2. Когда автоотклик активен, `SchedulerService` запускает фоновый цикл:

- **Проверка лимита:** Считает количество записей в `application_records` за текущие сутки (с `00:00:00`). Если достигнут `DAILY_LIMIT`, процесс засыпает до следующего дня и уведомляет пользователя в Telegram.
- **Поиск:** Запрашивает подходящие вакансии через открытый API `GET https://api.hh.ru/vacancies` по фильтрам из БД. Отсеивает те, что уже есть в `application_records`.
- **Отклик:** Для каждой новой вакансии скачивает описание через API, генерирует письмо в `LlmService` и вызывает `HhHybridService.applyToVacancy()` в полностью скрытом режиме (`headless: true`). Браузер открывает страницу вакансии, выбирает резюме, вставляет сопроводительное письмо и отправляет отклик.
- **Сохранение и пауза:** Записывает результат в `application_records` и ждет случайную паузу **от 2 до 5 минут** перед следующей вакансией.

### 5.5. Проверка статусов и уведомления (в том числе после выключения ПК)

1. При каждом запуске приложения на ПК, а также каждые 15 минут по таймеру `croner`, запускается метод `syncNegotiations()`.
2. Скрытый браузер Playwright открывает страницу `https://hh.ru/applicant/negotiations` и считывает актуальные статусы откликов (Приглашение, Отказ, Просмотр) и сообщения от работодателей.
3. Если статус в базе изменился, программа обновляет запись в `application_records` и ставит `isNotified = false`.
4. Затем программа выбирает все записи с `isNotified == false` и отправляет по каждой уведомление в Telegram (с названием компании, вакансией, новым статусом и ссылкой), после чего ставит `isNotified = true`.

### 5.6. Генерация Excel-отчетов и задел под Google Таблицы

1. Создается единый интерфейс `IReportExporter`.
2. Основная реализация `ExcelExporterService` (на базе `exceljs`) формирует `.xlsx` файл со столбцами: **Дата**, **Компания**, **Позиция**, **Зарплата**, **Статус**, **Ссылка на вакансию**, **Сопроводительное письмо**. Файл отправляется пользователю прямо в чат Telegram по нажатию кнопки `📊 Скачать отчет (Excel)`.
3. Рядом создается класс-шаблон `GoogleSheetsExporterService` для будущей бесшовной интеграции с Google Docs/Sheets.

## 6. Пошаговый план разработки для ИИ-агента (Фазы)

Разрабатывай приложение последовательно по этим 5 фазам, проверяя код компилятором `tsgo` на каждом этапе:

- **Фаза 1 (Основа, TypeScript 7 и база данных):** Инициализировать проект под Node.js 26 (`"type": "module"`), подключить компилятор TypeScript 7 (`@typescript/native-preview` / `tsgo`), настроить **Drizzle ORM** со встроенным драйвером `node:sqlite`, описать таблицы в `src/db/schema.ts`, написать сервис настроек `ConfigStoreService` и консольный опрос при первом запуске в `src/main.ts`.
- **Фаза 2 (Гибридный модуль HH и нейросеть):** Реализовать `HhHybridService` (поиск вакансий через `ofetch`, интерактивный вход, чтение резюме, отправка откликов и парсинг статусов через `playwright`) и `LlmService` (генерация писем через `gemma4:64k`).
- **Фаза 3 (Telegram-бот и управление):** Собрать бота на `grammy`, сделать главное меню, кнопку запуска окна входа в HH, загрузку PDF-резюме через `unpdf`, настройку фильтров поиска и установку дневного лимита (с валидацией `<= 100`).
- **Фаза 4 (Фоновая автоматизация):** Реализовать `SchedulerService` на базе `croner` (цикл автооткликов с проверкой дневного лимита и случайными паузами 2–5 минут + синхронизация статусов при старте ПК и каждые 15 минут).
- **Фаза 5 (Отчеты):** Реализовать `ExcelExporterService` на базе `exceljs`, подключить отправку файла в Telegram и создать интерфейс-заглушку для Google Sheets.
